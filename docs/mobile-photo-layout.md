# スマホの写真配置

620px以下のホーム写真は、CSSの段組みではなく、`src/lib/photo-layout.ts`の計算で2列へ配置する。既存の写真抽選・ピン・揺れ・激レア演出は維持する。

## 計算すること

1. ボードの実際の幅から2列の幅を決める。
2. 写真の台紙を、その幅で実測する。`offsetHeight`には画像だけでなく、キャプション・台紙の余白も含まれる。
3. 上辺のピンを支点に左右7度まで揺れたときの範囲を求める。回転の端点だけでなく、その途中で角が最も出っ張る角度も調べる。ピンと影の余白も加える。
4. その範囲が列の内側へ収まる大きさに写真全体を縮め、今の下端が低い列へ順番に置く。同じ高さなら左を選ぶ。
5. 左右のうち最も下にある写真の範囲まで、ボード自体の高さを確保する。フッターはその後ろに通常の文書配置で続く。

スマホの最初の傾きと揺れも同じ±7度に収める。写真が動いている間も、計算済みの場所からはみ出さず、横へ大きく振れる分の余白で写真を小さくしすぎないための制約。PCの揺れや配置には適用しない。PCからスマホ幅へ変えたときも、その時点で傾きをこの範囲へ戻す。

## サイズが変わるとき

`src/lib/actions/mobilePhotoLayout.ts`がボードと台紙を`ResizeObserver`で観察し、幅や実測高さが変わったら再配置する。画像の読み込み完了・エラー、Webフォントの準備完了、表示する写真の入れ替わり、スマホとPCの切り替えも対象。高さは変形後の見かけの大きさで測らず、未変形の台紙を使うため、再計算のたびにサイズが膨らむことはない。

計算完了は`.photo-board[data-mobile-layout="ready"]`で判定できる。PCへ戻るとこの属性と配置用クラスを外し、従来の左右の写真列へ戻る。監視とイベントはコンポーネントの破棄時に解除する。

JavaScriptが無効なとき・初回計算前は、通常の2列CSS Gridで写真を文書の流れに載せる。CSS段組みで写真の途中やピンが別の段へ分かれる状態を避ける。写真の抽選方法や本文・フッターは変えず、写真領域が実際に使う場所を管理する修正。

`scripts/photo-layout.test.mjs`では、狭幅・縦長横長混在・画像失敗相当の小さい高さ・奇数枚・空配列・再計算と、揺れの途中の四隅が予約範囲を出ないことを確認する。
